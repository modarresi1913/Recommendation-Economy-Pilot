# Data Dictionary

This directory holds the collected responses, annotations, Gold Standard, and adjudication records for the ARS measurement study.

## File inventory

| File | Description | Schema |
|---|---|---|
| `responses.jsonl` | One record per AI response (full text, model version, self-disclosure, citations) | [`schema/response-record.schema.json`](../schema/response-record.schema.json) |
| `annotations.jsonl` | One record per brand–response event (class code, subtype, strength, evidence span, rationale) | [`schema/ars-record.schema.json`](../schema/ars-record.schema.json) |
| `gold-standard.jsonl` | Frozen ≥50-event subset with full multi-coder agreement (post-adjudication); used for onboarding and LLM calibration (R-R.5) | [`schema/ars-record.schema.json`](../schema/ars-record.schema.json) |
| `adjudications/` | Adjudication decision records (per R-A.9, R-A.10), versioned with the protocol | — |

## Validation

Before any release, validate the dataset:

```bash
python validation/validate.py \
    --responses data/responses.jsonl \
    --annotations data/annotations.jsonl \
    --strict
```

Exit code must be 0. See [`validation/README.md`](../validation/README.md) for error/warning codes.

## Privacy note

The dataset contains **public AI responses** — text generated by AI platforms in response to standardized buyer-intent questions. **No personal data is collected.** The buyer personas in the question registry are fictional scenarios, not real individuals.

Before release, confirm:
- [ ] No PII (personally identifiable information) in any `full_text` field.
- [ ] No API keys or credentials leaked in any field.
- [ ] No real user names, emails, or phone numbers in citations or response text.
- [ ] `model_version` fields do not contain proprietary or non-public identifiers.

If any PII is found, redact before release and document the redaction in the release notes.

## Zenodo release procedure

To archive a release on Zenodo and obtain a DOI:

1. **Create a GitHub release tag** — tag the commit as `v1.x.0` (matching the protocol version) on the [releases page](https://github.com/modarresi1913/Recommendation-Economy-Pilot/releases/new).
2. **Zenodo "New version"** — go to [Zenodo](https://zenodo.org), log in, and create a new version of the repository deposit (or create a new deposit if this is the first release).
3. **Upload the tag archive** — download the GitHub release archive (`.tar.gz` or `.zip` from the release page) and upload it to Zenodo. Alternatively, connect Zenodo to the GitHub repository for automatic archiving on release.
4. **Copy the DOI** — Zenodo assigns a DOI (e.g., `10.5281/zenodo.XXXXXXX`). Copy it.
5. **Uncomment the README's Zenodo badge** — in [`README.md`](../README.md), uncomment and fill the DOI badge line:
   ```markdown
   [![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.YOUR_DOI.svg)](https://doi.org/10.5281/zenodo.YOUR_DOI)
   ```
6. **Cite the DOI** — in any publication or article, cite the DOI in the Data availability section. Example: "The dataset and protocol are archived at Zenodo (https://doi.org/10.5281/zenodo.XXXXXXX)."
7. **Commit the README update** and push.
